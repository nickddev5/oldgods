# 2. The world is built in code from the run seed

Date: 2026-10-09. Status: accepted.

## Context

Every map is random, and agents work on this project without seeing the Editor. Hand-built scenes are hard to review in diffs and easy to break by accident, and Nick's Editor must never have its open scenes saved or discarded by tooling.

## Decision

- Scenes hold one entry component (`RunController`) and a reference to `Resources/GameAssets`. The run builds ground, light, player, camera, horde and HUD in code at start.
- Assets that can be generated (materials, content assets, scenes, build settings) are generated by `Old Gods > Build > Everything`, which keeps GUIDs stable, keeps Inspector tuning on content assets, and builds scenes additively without touching open scenes.
- The ground is a `HeightField` (pure C#, unit-tested) rendered as flat-shaded mesh chunks, not a Unity `Terrain`.
- Shaders are hand-written HLSL rather than Shader Graph assets.

## Consequences

- Visual checks need a running build: `python Tools/smoke.py --shots DIR` saves screenshots of a scripted run, so an agent can look at the result.
- Level dressing that needs hand placement (the throne room, set pieces) will need prefabs that the code places; that is fine.
- Shader Graph tooling is not available for these shaders; changes are made in `Assets/OldGods/Shaders/*.hlsl`.
